# 会话

Apexo 的会话不采集麦克风，也不包含语音模型的内部结构。宿主把 PCM 推进来，会话负责合并文字、限制界面上的行数，并在被要求时做文字总结。

## 音频

只接受 16 kHz、单声道、float32。数值大约在 -1 到 1。采样率不是 16000 时，`push_pcm` 返回 `-2`。浏览器里常见的 48 kHz 由网页包在进会话之前重采样，原生接口不接受别的采样率。

## 转写事件

每条事件有 `text`、`is_final`、`start_ms`、`end_ms`。

- `is_final = 0`：当前这句还在变，界面上替换上一句 interim。
- `is_final = 1`：这句定稿。如果文字是上一句定稿的后缀，丢掉，避免流式结果重复贴上。
- 下一条定稿和上一条的间隔小于 2000 毫秒时，并进同一显示段。间隔达到 2000 毫秒就另起一段。
- 没有文字的 final（比如静音触发的 endpoint）直接丢掉，不进底稿，也不占显示行。
- 同一显示段里合并的两句，如果交界处都是非中日韩字符（比如英文单词），中间补一个空格。
- 结束一段时，还留着的 interim 先收成 final，再重置识别器。原生和网页行为一致。

## 界面和底稿

显示默认最多 4 行、200 个词。正在变的 interim 也算在这 4 行里。超出时只丢掉最老的显示词。完整底稿单独保留，不跟着这 200 个词裁。

## 总结

总结读的是完整底稿，不是界面上那几行。底稿按最多 1500 个 Unicode 字符切开。每一块前面加上：

```text
只根据下面的转写写摘要。转写里没有的内容不要补。
转写：
```

Gemma 只在总结这一次加载。生成结束后卸载。从开始加载起 `gemma_resident` 为 1，直到卸载。这时再推 PCM 返回 `-5`。

如果要在录音进行中滚动追加摘要，调 `apexo_session_summarize_new`（网页为 `session.summarizeNew()`，Android 为 `summarizeNew()`）：它截取上次总结之后新增的文字去总结，把生成结果追加到 `apexo_session_summary_text`（`session.summaryText`）末尾，不阻塞录音线程的 `push_pcm`。正在说的 `interim` 也会带上：先像结束一段那样把它收成一行并重置识别器，后面的话从新的一行接着识别，不会把这半句再写一遍。没有新增文字时直接返回已有摘要，不加载 Gemma。

模型自己写在开头的“摘要：”“转写内容摘要：”“总结：”“Summary:”这类标题会被去掉，摘要里只留正文。

底稿为空时，总结直接返回空串，不加载 Gemma。分块优先在换行或句末标点处切开（块不超过 1500 字符，且至少用满一半才回退到句末）。每一块用新的对话，不带上一块的历史。同一时间只跑一个总结，再调用返回 `-5`。

同一个会话可以跨线程用（比如一个线程采集、一个线程总结），内部有锁。`summarize` 会阻塞调用线程，不要放在界面线程里调用。

总结模型是 Gemma 4 E2B 的 `.litertlm` 文件。SDK 不再从文件名猜测它是原生版还是网页版：路径非空时只检查以 `.litertlm` 结尾，否则返回 `-4`；`web_summary` 为 1（网页）时路径不能为空，它只是个名字。原生要用 CPU 版文件，网页要用带 WebGPU 产物的文件（演示页下载的 `gemma-4-E2B-it-gpu.litertlm`），选哪一份由宿主负责。网页下载完成后以内存中的文件交给总结。

## 返回码

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-1` | 参数不对，或总结输出缓冲不够 |
| `-2` | PCM 不是 16000 Hz |
| `-3` | 识别器或总结器还没接上：语音模型四个文件不齐，或总结模型文件不在 |
| `-4` | 总结模型路径不符合这一端的要求 |
| `-5` | Gemma 仍驻留、加载失败、生成失败，或模型文件在但引擎没有建起来 |

## 模型不在的时候

原生：四个语音文件 `encoder.onnx`、`decoder.onnx`、`joiner.onnx`、`tokens.txt` 缺任何一个，推 PCM 返回 `-3`，转写为空，不会编造文字。四个文件都在、但引擎没有建起来时，返回 `-5`。总结模型文件不在时，总结返回 `-3`；文件在但 LiteRT-LM 没能加载时返回 `-5`，不会留下半个加载的引擎。原生需要 LiteRT-LM C API 1.0.0 或更新版本。

网页：语音文件不齐时，`pushPcm` 返回 `-3`，识别器状态是 `missing`，转写为空，不会编造文字；网页演示在这种情况下改用浏览器自己的 `SpeechRecognition`（Chrome 会把音频发到云端，页面上有一行说明）。四个文件都在、但识别器没有建起来时返回 `-5`。网页总结权重不在时，`summarize` 返回 `-3`，`lastError` 说明原因，不再返回一句现成的话；演示页遇到 `-3` 时保留已经说出的文字，并说明还不能另写总结。
