# 会话

Apexo 的会话不采集麦克风，也不包含语音模型的内部结构。宿主把 PCM 推进来，会话负责合并文字、限制界面上的行数，并在被要求时做文字总结。

## 音频

只接受 16 kHz、单声道、float32。数值大约在 -1 到 1。采样率不是 16000 时，`push_pcm` 返回 `-2`。浏览器里常见的 48 kHz 由网页包在进会话之前重采样，原生接口不接受别的采样率。

## 转写事件

每条事件有 `text`、`is_final`、`start_ms`、`end_ms`。

- `is_final = 0`：当前这句还在变，界面上替换上一句 interim。
- `is_final = 1`：这句定稿。如果文字是上一句定稿的后缀，丢掉，避免流式结果重复贴上。
- 下一条定稿和上一条的间隔小于 2000 毫秒时，并进同一显示段。间隔达到 2000 毫秒就另起一段。
- 结束一段时，还留着的 interim 先收成 final，再重置识别器。

## 界面和底稿

显示默认最多 4 行、200 个词。超出时只丢掉最老的显示词。完整底稿单独保留，不跟着这 200 个词裁。

## 总结

总结读的是完整底稿，不是界面上那几行。底稿按最多 1500 个 Unicode 字符切开。每一块前面加上：

```text
只根据下面的转写写摘要。转写里没有的内容不要补。
转写：
```

Gemma 只在总结这一次加载。生成结束后卸载。加载期间 `gemma_resident` 为 1。这时再推 PCM 返回 `-5`。

网页会话要求模型路径里含有 `-web`，例如 `gemma-4-E2B-it-web.litertlm`。原生会话拒绝这种路径，它用的是不带 `-web` 的 Gemma 4 E2B `.litertlm`。演示页下载的 `gemma-4-E2B-it-gpu.litertlm` 是网页权重本身，下载完成后以内存中的文件交给总结，路径检查仍用带 `-web` 的名字。

## 返回码

| 码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-1` | 参数不对，或总结输出缓冲不够 |
| `-2` | PCM 不是 16000 Hz |
| `-3` | 识别器或总结器还没接上 |
| `-4` | 总结模型路径不符合这一端的要求 |
| `-5` | Gemma 仍驻留、加载失败、生成失败，或模型文件在但引擎没有建起来 |

## 模型不在的时候

四个语音文件 `encoder.onnx`、`decoder.onnx`、`joiner.onnx`、`tokens.txt` 缺任何一个，原生推 PCM 才会给出占位句「你好，这是已经成稿的一句。」网页演示在这种情况下不把占位句画出来，改用浏览器自己的语音识别。四个文件都在、但引擎没有建起来时，不退回占位句，推 PCM 返回 `-5`，转写为空。

总结权重不在时，原生返回「模型文件不在，未调用 LiteRT-LM。」网页返回「（网页版 Gemma 权重由宿主提供，这里只提交转写文本）」。演示页遇到这句时保留已经说出的文字，并说明还不能另写总结。
