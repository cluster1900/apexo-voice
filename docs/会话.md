# 会话（0.2.0）

Apexo 的会话负责管理流式转写底稿、实时显示窗口、增量阶段摘要游标与按需文字总结。宿主负责麦克风采集、权限与界面。

## 音频输入

原生接口 `apexo_session_push_pcm`（及 Android `pushPcm`）接收 16 kHz、单声道、float32 PCM（范围约 `-1.0` 到 `1.0`）；采样率不是 `16000` 时返回 `-2`。

Web 接口 `session.pushPcm(pcm, sampleRate)` 支持任意正整数采样率（如浏览器常见的 `48000` Hz），内部通过带低通滤波的流式重采样器转为 16 kHz 后送入识别 Worker。

## 转写事件与回调

每条转写事件包含 `text`、`is_final`（Web/Java 为 `isFinal`）、`start_ms`（`startMs`）、`end_ms`（`endMs`）：

- `is_final = 0`：当前语句仍在变化（草稿 `interim`），界面上替换上一条 `interim`。
- `is_final = 1`：语句已定稿（`final`）。若文本与上一条定稿时间轴重叠且是其后缀，自动去重。
- 相邻两条 `final` 间隔小于 `2000` 毫秒时合并在同一显示行（非中日韩单词交界处自动补空格）；间隔达到 `2000` 毫秒时另起一行。完整底稿 `full_transcript` / `fullTranscript` 中每条定稿以换行符 `\n` 分隔保存。
- 没有文字的空 `final`（如静音触发的空 endpoint）直接忽略，不进底稿也不触发回调。
- **结构化事件回调**：
  - C：`apexo_session_set_transcript_callback(session, callback, user)`
  - Android Java：`session.setTranscriptListener(event -> ...)`
  - Web：`createSession({ onTranscript(event) { ... } })`
  - 每次 `interim` 变化及每条去重后的有效 `final`（含合并到同一显示行的 `final` 与 `endSegment` 刷出的尾句）都会在会话内部锁释放后触发回调，回调内可安全读取 `display_text` 与 `full_transcript`。

## 停止录音与尾帧收尾（`endSegment`）

当用户点击“停止录音”时，话音刚落尚未经过长静音，流式识别器内部仍有尾帧尚未吐出。调用 `apexo_session_end_segment` / `session.endSegment()` 时：

1. Web 端先 `flush()` 流式重采样器，将残留采样送入识别器。
2. 识别器调用 `InputFinished` 通知流输入结束，送入内部尾部静音帧（仅用于推进解码器窗口，不计入用户录音时间轴）并解码至 `isReady` 为假。
3. 若解码出非空尾句，作为唯一一次 `final` 入稿并关闭当前显示段，随后销毁已结束的流并创建新流，保留已加载的识别器权重供下一段录音复用。
4. 紧接着调用 `summarize()` 即可包含用户说出的最后一个词，无需人为拼接数秒静音。

## 三种总结入口与并发模型

| 入口 | C API | Android Java | Web JS | 读取范围 | 会话状态更新 |
| --- | --- | --- | --- | --- | --- |
| 阶段摘要 | `apexo_session_summarize_new` | `summarizeNew()` | `await session.summarizeNew()` | 上次摘要游标到当前已定稿底稿末尾的新增 `final` | 追加到 `summary_text` 并推进游标 |
| 完整总结 | `apexo_session_summarize` | `summarize()` | `await session.summarize()` | 当前已定稿完整底稿 `full_transcript` 快照 | 替换 `summary_text` 并将游标推到快照末尾 |
| 纯文本总结 | `apexo_session_summarize_text` | `summarize(String text)` | `await session.summarize(text)` | 调用方传入的外部 UTF-8 字符串 | **不读取也不修改** `full_transcript`、`summary_text`、游标或识别器 |

### 快照与非阻塞录音保证

1. **不触碰 `interim`、不重置识别器**：`summarize()` 与 `summarizeNew()` 只读取调用瞬间已定稿的 `full_transcript` 快照，绝不把正在说的 `interim` 强行定稿，也不调用 `asr_reset`。
2. **总结期间不阻塞 `push_pcm`**：Gemma 加载、推理、卸载全过程在会话互斥锁外执行。总结运行期间（`gemma_resident == 1`），录音线程继续调用 `push_pcm` 均正常返回 `0` 并进入 ASR，期间产生的新 `final` 留给下一次 `summarizeNew()` 或 `summarize()` 处理。
3. **单会话总结互斥（`APEXO_ERR_BUSY = -6`）**：同一会话同一时刻只允许运行一个总结任务。总结进行中再次调用任一总结接口，C 返回 `APEXO_ERR_BUSY (-6)`，Java 抛出含 `code -6` 的 `IllegalStateException`，Web 返回带 `err.code = -6` 的 rejected Promise。
4. **失败原子性**：若模型文件缺失（`-3`）、加载或生成失败（`-5`）、C 输出缓冲不足（`-1`），原有的 `summary_text` 与增量游标保持不变。
5. **空输入不加载模型**：无已定稿文字、无新增 `final`、或外部传入纯空白字符串时，直接成功返回（`summarize` / `summarize_text` 返回 `""`，`summarize_new` 返回已有 `summary_text`），不加载 Gemma。

### 分块提取与跨块汇总归纳

默认切块上限为 `1500` 个 Unicode 字符（优先在换行或句末标点处切分）：

- **`summarizeNew()`（阶段摘要）**：对本次新增的 `final` 按块提取简洁事实摘要并追加到 `summary_text`。
- **`summarize()` 与 `summarize_text()`（完整总结）**：
  - 输入不超过 1500 字符时，单次调用生成完整总结。
  - 输入超过 1500 字符时，先按时间顺序逐块生成简洁事实摘要（保留决定、待办、负责人、时间及对先前决定的修改/撤销），再将各块摘要组合执行一次整体归纳（合并重复项，对后续被修改或撤销的决定以最终决定为准）。若中间摘要仍超过切块上限，则按序分组归约直至收敛；若归约未缩短输入则返回 `-5` 并保留旧摘要。
  - 单次总结请求只加载/卸载一次 Gemma，各分块与归纳步骤之间重建 `Conversation`，不重复加载模型权重。

分块阶段提示词：

```text
仅依据以下转写提取简洁事实摘要。
保留决定、待办、明确的负责人和时间，以及对先前决定的修改或撤销。
没有明确给出的信息不要补充；尚未确定的事项保持未确定。
按原文发生顺序概括，保留“取消”“改为”“最终决定”等关系。
转写：
```

整体归纳提示词：

```text
以下内容按会议发生顺序排列。请归纳成一份简洁的会议总结。
合并重复事项；对于明确被后续内容修改或撤销的决定，以最后明确决定为准。
保留仍未确定或互相矛盾且没有结论的事项，不自行猜测。
只写材料中有依据的要点、最终决定和待办，不补负责人或日期。
材料：
```

## 会话重置与销毁

- **清空当前会话（`reset`）**：C `apexo_session_reset(session)`、Java `session.reset()`、Web `session.reset()`（`release()` 作为兼容别名保留）。清空底稿、显示文本、摘要、增量游标与 `interim`，重置识别流并将会话音频时间轴归零，同时保留已加载的识别器权重供下一场录音立即使用。若在总结运行期间调用 `reset()`，旧总结完成时检测到 `epoch` 变化会自动丢弃结果，不会写回新会话。
- **销毁会话（`destroy` / `close` / `dispose`）**：C `apexo_session_destroy(session)`、Java `session.close()`、Web `await session.dispose()`。若后台仍有总结正在运行，等待其安全完成卸载后再释放底层资源。

## 返回码

| 返回码 | 常量 | 含义 |
| --- | --- | --- |
| `0` | — | 成功 |
| `-1` | — | 参数无效（如空指针、长度不合法）或 C 总结输出缓冲区容量不足 |
| `-2` | — | 原生 `push_pcm` 采样率不是 `16000` Hz，或 Web `sampleRate` 非法 |
| `-3` | — | 模型文件缺失：ASR 四个文件（`encoder.onnx`/`decoder.onnx`/`joiner.onnx`/`tokens.txt`）不齐，或总结 `.litertlm` 文件不存在 |
| `-4` | — | 总结模型路径不合法（如为空或未以 `.litertlm` 结尾） |
| `-5` | — | 引擎运行失败：模型文件存在但识别器/LiteRT-LM 未能初始化、总结生成失败、或跨块归约未收敛 |
| `-6` | `APEXO_ERR_BUSY` / `ERR_BUSY` | 当前会话已有总结任务正在执行 |
