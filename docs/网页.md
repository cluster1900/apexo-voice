# 网页

网页包是 `@apexo/sdk`，源码在 `web/src/`。演示在 `web/demo/`，由 `node server.js` 提供，默认 `http://127.0.0.1:4173/`。响应带 `Cross-Origin-Opener-Policy: same-origin` 和 `Cross-Origin-Embedder-Policy: require-corp`，LiteRT-LM 的线程版 WebAssembly 需要这个隔离。

## 页面上的按钮

- **开始录音**：清空上一段，打开麦克风。处理关闭回声消除、噪声抑制和自动增益。优先用 16 kHz 的 `AudioContext`。采集走 AudioWorklet，混成单声道，经静音增益接到输出，避免 Chrome 停止拉流，也不把声音放出来。
- **结束**：停掉麦克风和识别，把这一段冻结。状态是「这一段已结束」。还没开始就点，状态是「还没有开始录音」。
- **总结**：只在点击时运行。还在录音就先结束。没有文字时状态是「还没有可总结的文字」，不会去加载 Gemma。有文字才总结。权重还没准备好时，已经说出的字留在上面。
- **回听刚才这一段**：播放从开始到结束收下来的那段 PCM。没有这段时状态是「还没有可回听的一段」。
- **下载 Gemma 4 E2B**：下载 `gemma-4-E2B-it-gpu.litertlm`，大约 2 GB。进度写在按钮下面。下完之后再点总结，用的就是这份权重。

打开页面时转写区是空的，不会先放占位句，也不会去请求 Gemma。

## 字从哪里来

语音模型四个文件不齐时，演示用浏览器的 `SpeechRecognition`（`zh-CN`、连续、带 interim）。识别事件进 `pushAsrEvent`，不把占位 PCM 推进会话。四个文件齐、识别器处于 live 时，才把采集到的 PCM 推进 sherpa-onnx，并且不再启动浏览器识别。

浏览器拒绝麦克风、识别服务不可用或网络失败时，状态是「浏览器没能把声音转成文字」，并且不会反复重启。

## 总结权重

演示服务器把 Hugging Face 上的文件代理到：

`/download/gemma-4-E2B-it-gpu.litertlm`

来源是 `litert-community/gemma-4-E2B-it-litert-lm` 里的 `gemma-4-E2B-it-gpu.litertlm`。页面把下完的字节交给 `setSummaryModel`。LiteRT-LM 的脚本和 wasm 由演示服务器从 `web/node_modules` 的 `/vendor/` 路径提供，不从页面直接跨站拉取。

本地文件是否存在，用带 `X-Apexo-Probe: 1` 的 HEAD 判断。文件不在时演示服务器返回 204，避免浏览器把一次探测记成失败的资源加载。只有 200 才算文件在。
