# 平台包

五个包同一套调用：创建会话、推入 PCM、读转写、结束一段、总结底稿、释放。前四个包链接 `native/` 里的同一份 C++。网页包是 JavaScript。

模型文件不放进包里。宿主把语音模型和 Gemma 权重放在自己的目录或 URL。

## 交付

| 包 | 形态 | 转写 | 总结 |
| --- | --- | --- | --- |
| Android | `apexo-session.aar` | sherpa-onnx | LiteRT-LM |
| iOS | `ApexoSession.xcframework` | sherpa-onnx | LiteRT-LM |
| macOS | `libapexo_session.dylib` 加 `apexo_session.h` | 同一份 C++ | LiteRT-LM |
| Windows x64 | `apexo_session.dll` 加头文件 | 同一份 C++ | LiteRT-LM |
| Web | npm `@apexo/sdk` | sherpa-onnx，模型文件齐了才走这条 | `@litert-lm/core`，WebGPU |

Windows 这一版是 x64。打包脚本是仓库根目录的 `pack.sh`，产物在 `dist/`。`dist/` 不提交。

公开头文件是 `native/include/apexo_session.h`。Android 的 Java 类是 `com.apexo.sdk.ApexoSession`，库名 `apexo_session`。

## 引擎从哪里加载

原生默认引擎用 `dlopen` 找 sherpa-onnx 和 LiteRT-LM。可以用环境变量改路径：

- `APEXO_SHERPA_LIBRARY`
- `APEXO_LITERT_LIBRARY`

没设置时，macOS 找 `libsherpa-onnx.dylib` 和 `liblitert_lm.dylib`，Windows 找对应的 DLL，Linux 和 Android 找 `.so`。

## 模型文件

原生四个包共用一份 Gemma 4 E2B `.litertlm`，文件名不要含 `-web`。转写目录里要有 `encoder.onnx`、`decoder.onnx`、`joiner.onnx`、`tokens.txt`。有 `silero_vad.onnx` 时一并接上。

手机上不要让语音模型和 Gemma 同时常驻。转写结束再加载 Gemma，总结完卸载。会话本身会在总结期间拒绝新的 PCM。

网页必须用带 WebGPU 产物的权重。普通 `.litertlm` 在浏览器里加载会失败。网页版 Gemma 只走 WebGPU。桌面 Chrome、Edge 113 及以上，并且页面带 COOP/COEP，才在保证范围内。手机浏览器不保证。

## 宿主自己做的部分

- 麦克风和系统声音。Android 用 `AudioRecord`，iOS 和 macOS 用 `AVAudioEngine`，Windows 由宿主采集，网页用 `getUserMedia`。iOS 演示在 `ios-demo/`。
- 权限、模型放在哪、界面。
- 问句检测和说话人分离。这两项不在这一版里。

浏览器不能静默抓别的应用的声音。`getDisplayMedia` 只能在用户同意后录当前标签页或屏幕里的声音。
